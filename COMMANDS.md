# Відповідність операцій CLI

Контракт за всіма 34 реєстраціями `linkedin-ex/mcp-server/index.js`. Усі команди реалізовано в сервісі й CLI та покрито автоматичними тестами з **фальшивим розширенням** (WebSocket-клієнт, що імітує `linkedin-ex` протокол): імена дій, форма аргументів, preview/`--confirm`, бюджет, пауза, `unverified`, черга. **Жодна команда не перевірялася на справжньому LinkedIn і справжньому Chrome-розширенні** — поведінка DOM, результати реальних сторінок і живий handshake лишаються неперевіреними. Успішний результат — JSON на stdout, помилки — JSON на stderr і ненульовий код (таблиця кодів у README). Псевдоніми: `queue add` = `queue enqueue`, `queue show` = `queue get`. Довідка: `linkedin <група> <команда> --help` (текст) або `--help --json` (структурована: опис, `sideEffect`, `notes`, `output`, `examples`, типи/діапазони/enum/default параметрів); також `linkedin help <група> [команда]`. Кожна команда з цієї таблиці має запис у `src/commands.ts`, це перевіряє `tests/help.test.ts`. Доповнення до таблиці: `linkedin service start|stop|resume` (керування сервісом), `--confirm` додається до всіх зовнішніх дій, `--key` до `queue enqueue`.

## Правила побічних дій

- Спільний бюджет зовнішніх дій: 15 за годину та 60 за добу; інтервал між ними 20–30 секунд. Запрошення додатково обмежені 20 за добу.
- Перед зовнішньою дією показувати точний preview; виконання потребує `--confirm`. Черга та універсальні browser click/type не повинні обходити ці правила.
- При checkpoint або captcha зупинити виконання. Якщо результат дії невідомий, зберегти `unverified`, перевірити LinkedIn і не повторювати її автоматично.
- Ці правила реалізовано в сервісі (не в інструкції агенту) й перевірено тестами з фальшивим розширенням. Бюджет рахується за журналом дій у SQLite, тож переживає перезапуск. `browser click` / `browser type` потребують `--confirm`, зупиняються при вичерпаному бюджеті й паузі, але самі в бюджет не рахуються (результат неможливо класифікувати). `invitation respond|withdraw` і `post delete-scheduled` потребують `--confirm`, але бюджет не витрачають (як у `linkedin-ex`). Прямі виклики понад ліміт відхиляються кодом `RATE_LIMIT` (6), завдання з черги чекають до `retryAt`.
- Не повторюються автоматично зовнішні дії зі станом `unverified`; для читальних завдань, перерваних падінням сервісу, повтор виконується.

Стандартні незалежні значення: порт `47851` (змінюється через `linkedin config set port N`, код помилки `PORT_IN_USE` = 8), каталог `~/.linkedin-cli`.
